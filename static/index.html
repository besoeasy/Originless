Two things to store, and nothing else to learn

  
Everything on a node is either a small signed event or a binary blob. An event can point at a blob by hash, so the two combine into whatever you need.

  

    

      
Signed events

      
JSON records that prove who wrote them. The node checks the Ed25519 signature before it accepts anything.

      
    
        
  • Group records by collection and tag them with labels
    • 
        
  • Each event expires on its own expires_at time
    • 
        
  • Filter with GET /events?collection=&label=&search=
    • 
        
  • Follow new events live at /events/stream
    • 
        
  • Link a file with the top-level "blob": "<sha256>" field
    • 
      

    

    

      
Binary blobs

      
Any binary blob, stored under the SHA-256 of its contents. Upload the same bytes twice and you get one copy.

      
    
        
  • Upload bytes and the event in one request (event part first); point at them with the top-level "blob": "<sha256>" field
    • 
        
  • Fetch the bytes back with GET /blob/<hash>
    • 
        
  • No size cap on the pool, so storage is limited only by your disk
    • 
        
  • Served with immutable caching, so CDNs and browsers keep them for a day
    • 
        
  • Clients can verify the download by hashing it again
    •

Six endpoints, all open

  
There is no login step. Events are trusted because of their signatures, and blobs because of their hashes.

  

    
EndpointWhat it does

    
      
POST /eventsPublish a signed JSON event with an expiry time.

      
GET /eventsList events, filtered by collection, label, search text, or ?blob=<sha256>.

      
GET /events/streamReceive new events as they arrive over Server-Sent Events.

      
POST /eventsPublish a signed event; add a second multipart part named blob (after the event part) to carry raw bytes in the same request.

      
GET /blob/<hash>Download a blob by hash.

      
GET /statusRead the node version, blob count, stored bytes, and event count.
